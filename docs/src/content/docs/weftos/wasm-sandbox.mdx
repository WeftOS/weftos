The WASM sandbox provides isolated tool execution with configurable resource limits. Tools run as WASM modules inside a Wasmtime runtime with fuel metering, memory caps, and optional WASI access.

**Source**: `crates/clawft-kernel/src/wasm_runner/` (`runner.rs`, `types.rs`, `registry.rs`, `catalog.rs`, `tools_*.rs`)
**Feature**: `wasm-sandbox` for the wasmtime runtime. It is off by default (`crates/clawft-kernel/Cargo.toml`); the module and tool catalog compile without it.

This is the kernel's tool sandbox. Cog workloads do not use it: WASM adapters for cogs use `clawft-wasm-host` (ADR-099 decision 4, `workload_runtime/mod.rs`).

## WasmToolRunner

```rust
pub struct WasmToolRunner {
    config: WasmSandboxConfig,
    // wasmtime Engine (wasm-sandbox); optional chain manager and governance engine (exochain)
}
```

Executes WASM modules with fuel metering (each instruction consumes fuel), memory limits via `ResourceLimiter`, and configurable timeout.

## Tool Lifecycle

```
Build -> Deploy -> Execute -> Version -> Revoke
```

All phases are chain-logged when `exochain` is enabled.

## Host Isolation

`wasi_enabled` defaults to false and `WasiFsScope` defaults to `None`, so a module gets no WASI filesystem access unless the config grants it. Fuel is metered (`consume_fuel`, `set_fuel`) and memory is capped through a wasmtime `ResourceLimiter` (`runner.rs`). The wasmtime sandbox-escape fix shipped in 0.8.4-rc.15 (wasmtime 48.0.7, CHANGELOG rc.15).

## Tool Signing (D9)

Ed25519 signing for tool provenance and integrity verification.

```rust
pub struct ToolSignature {
    pub tool_name: String,
    pub tool_hash: [u8; 32],
    pub signer_id: String,
    pub signature: Vec<u8>,     // Ed25519
    pub signed_at: DateTime<Utc>,
}
```

### Signature Verification

```rust
// Register a signed tool (the signature must verify against a trusted key)
registry.register_signed(tool: Arc<dyn BuiltinTool>, signature)?;

// Enforce signature requirement
registry.set_require_signatures(true);

// Manage trusted keys ([u8; 32] Ed25519 public keys)
registry.add_trusted_key(public_key);
```

`register_signed` fails with `InvalidSignature` unless some trusted key verifies the signature. Whether plain registration is refused when `require_signatures` is set was not re-checked for this page.

**Chain constant**: `EVENT_KIND_TOOL_SIGNED` logs signing events to ExoChain.

## Shell execution (D10)

```rust
pub struct ShellCommand { pub command: String, pub args: Vec<String>, pub sandbox_config: Option<SandboxConfig> }
pub struct ShellResult { pub exit_code: i32, pub stdout: String, pub stderr: String, pub execution_time_ms: u64 }
```

`execute_shell()` (`tools_sys.rs`) handles three built-ins, `echo`, `true` and `false`, and answers any other command with exit code 127 and `command not found` on stderr. Its own comment says compiling arbitrary commands to WASM and running them in the sandbox is future work, so there is no general shell here. With `exochain`, `EVENT_KIND_SHELL_EXEC` is available for logging.

## CompiledModuleCache

`CompiledModuleCache` (`runner.rs`) is a disk-persisted cache of compiled module bytes keyed by the module's 32-byte content hash, with a size cap, so a module is not compiled repeatedly. The earlier description of it as an LRU cache was not confirmed in the code read.
