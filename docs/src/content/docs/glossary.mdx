---
title: Glossary
description: Key terms, acronyms, and concepts used throughout WeftOS documentation.
---

## A

**Agent Loop**
The core execution cycle in clawft: receive message, build context, run pipeline stages, call tools, return response. See [Agent Loop](/docs/clawft/agent-loop).

**Analyzer / AnalyzerRegistry**
Pluggable trait-based assessment analyzers. The `AnalyzerRegistry` holds registered analyzers (complexity, dependency, security, topology, data source) and runs them during `weft assess`. Custom analyzers implement the `Analyzer` trait.

**AssessmentService**
Kernel-native `SystemService` that performs codebase analysis. Runs pluggable analyzers over the scoped files to produce findings, and logs operations to ExoChain. See [Assessment Workflow](/docs/weftos/guides/assessment).

**AppContext**
The top-level runtime container that holds the message bus, session manager, memory store, tool registry, and LLM adapter. Wrapped by the kernel's `Kernel<P>` struct.

## B

**Boot Sequence**
The ordered startup process: K0 kernel init, K1 process table, K2 IPC, ExoChain genesis, K3 WASM sandbox, then optional ECC and mesh layers. See [Boot Sequence](/docs/weftos/boot-sequence).

## C

**Cog**
A packaged, sandboxed workload that runs under the node daemon: a sensor driver, an inference step, an audio or camera pipeline. A cog has a `cog.toml` manifest and is placed on a node by governed placement (ADR-099, ADR-100). Cogs are built and catalogued in the separate `WeftOS/weftos-cogs` repository.

**Cog Host**
The service that runs cogs on a node. Its code moved to `WeftOS/weftos-cogs` in 0.8.4; the node daemon consumes it at a pinned revision.

**Cogbus**
The cog data-plane broker inside each node daemon (ADR-122). Cogs exchange readings, shared-memory streams, blobs and mesh topics through it, under governed subscriptions. Operate it with `weaver cogbus`.

**Chief of staff (CoS)**
The assistant surface that reads and acts across a user's devices and tools. Driven by `weft cos` (ADR-118).

**CBOR**
Concise Binary Object Representation. Used as the payload encoding inside RVF segments for compact binary serialization.

**clawft**
The agent runtime layer of WeftOS. Provides the LLM pipeline, tool system, skills, channels (Slack, Teams, CLI, web), and the browser WASM sandbox.

**clawft-rpc**
Shared RPC crate providing `DaemonClient` for both `weft` and `weaver` CLIs. Enables daemon-first operation with graceful local fallback. Uses line-delimited JSON over Unix domain socket.

## E

**Exposure**
A resource a node announces to the mesh so other nodes can see it, switch it off and read its log (ADR-120). Operate with `weaver expose`.

**ECC (Ephemeral Causal Cognition)**
The cognitive substrate layer. Maintains a causal DAG (directed acyclic graph), HNSW vector memory, impulse queue for ephemeral signals, and a cognitive tick loop that runs continuous reasoning. See [ECC](/docs/weftos/ecc).

**ExoChain**
A tamper-evident append-only hash chain (SHAKE-256) that records every significant kernel event. Provides cryptographic provenance for agent actions. See [ExoChain](/docs/weftos/exochain).

## G

**Gate**
The governance enforcement point. Every agent action passes through a gate that checks capabilities, constitutional rules, and resource limits before allowing execution.

**GGUF**
A quantized model format used for local inference. clawft does not load GGUF files itself; it talks to servers that do (llama.cpp, Ollama) through the `local/` and `ollama/` providers.

## H

**HNSW**
Hierarchical Navigable Small World graph. The vector search index used by ECC for nearest-neighbor retrieval over agent memory embeddings.

## I

**IPC (Inter-Process Communication)**
The K2 messaging layer. Agents communicate via typed message envelopes with A2A routing, pub/sub, and cron scheduling. See [IPC](/docs/weftos/ipc).

## K

**K-Phases**
The kernel build phases: K0 (boot), K1 (processes), K2 (IPC), K3 (WASM sandbox), K3c (ECC cognitive), K4 (containers), K5 (apps), K6 (mesh). See [Kernel Modules](/docs/weftos/guides/kernel-modules).

**Kernel**
The central `Kernel<P: Platform>` struct that manages the agent fleet. Wraps AppContext with process tracking, service lifecycle, IPC, health monitoring, and a boot state machine.

## M

**MeshId**
The identity of a named mesh, created with `weaver mesh create` and exported or imported as a signed record with `weaver mesh export` and `weaver mesh import`.

**Mesh**
The peer-to-peer networking layer for cross-node coordination. Supports encrypted transport (QUIC, Noise), discovery, and state replication without central servers. See [Mesh Networking](/docs/weftos/mesh-networking).

## N

**Node daemon**
The per-user `weaver` daemon on a machine. It hosts a kernel per project, runs cogs, brokers cog data and joins the machine to the mesh (ADR-103). Start it with `weaver kernel start`.

## P

**Placement**
The governed decision of which node runs a workload, based on signed node facts (ADR-099). See `weaver workload`.

**Project kernel**
The kernel for one registered project, run under the user daemon. Manage with `weaver project add|up|down|status|remove` (ADR-103).

**PID (Process ID)**
Every agent gets a unique PID from the kernel's process table, enabling supervision, resource limits, and lifecycle management.

**Pipeline**
The multi-stage message processing chain in clawft: context building, tool selection, LLM inference, response formatting. Configurable with custom stages.

**Platform**
The trait abstraction (`Platform`) that lets WeftOS run on native (Linux, macOS, Windows), Docker, WASI, and browser WASM with the same kernel code.

## R

**Router**
The tailnet router in the user daemon: one HTTPS front door per machine that serves each project by path (ADR-116). Off by default; operate with `weaver route`.

**RVF (Rust Vector Format)**
A binary segment format for storing embeddings, metadata, and knowledge bases. Uses 64-byte aligned segments with CBOR payloads and optional WITNESS chains for tamper evidence.

**ruvector**
The upstream ecosystem of Rust crates providing vector search, neural routing, consensus, and distributed coordination. WeftOS integrates `ruvector-cluster`, `ruvector-core`, and related crates.

## S

**SONA (Self-Optimizing Neural Architecture)**
A learning system that records agent decision trajectories and uses them to improve routing and model selection over time.

## W

**WASI (WebAssembly System Interface)**
The WASM runtime target for server-side deployments. WeftOS builds for `wasm32-wasip2` with HTTP, filesystem, and environment access.

**WASM (WebAssembly)**
The browser build target (`wasm32-unknown-unknown`). Enables running the full clawft agent runtime in a web browser via wasm-bindgen.

**Weaver**
Two things share the name. `weaver` is the operator CLI and node daemon binary. In the ECC layer, the Weaver is the cognitive modeler that runs the HYPOTHESIZE-OBSERVE-EVALUATE-ADJUST loop on causal models within the kernel.

**WeftOS**
The complete AI agent operating system: clawft (agent runtime), the kernel (OS abstractions), ECC (cognitive substrate) and the node daemon that hosts them and joins machines into a mesh.

**WITNESS Chain**
A hash chain appended to RVF segment files that proves the integrity of embedded knowledge. Each operation is cryptographically linked to the previous, creating tamper-evident provenance.
