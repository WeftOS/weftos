# Daemon RPC reference

Generated by `scripts/gen-rpc-reference.py` from the dispatch tables in `crates/clawft-weave/src`. Do not edit by hand; run `scripts/build.sh gen-rpc-reference`.

The daemon speaks JSON-RPC over its unix socket (and the authenticated TCP relay). Each request names a method; the daemon resolves the capability the method needs, checks the caller's scopes, then dispatches. Capabilities, lowest to highest: `Read`, `Chat`, `Write`, `Admin`. A method missing from the capability table defaults to `Read`.

There are three registration paths, all listed below:

1. **Core methods**: arms of the big `match` in `daemon.rs` `dispatch`, plus module dispatchers it forwards prefixes to.
2. **Extension routes**: the `ROUTES` table in `rpc_ext.rs`. Each route is a method prefix (ends in `.`) or an exact name, with an explicit capability. Routes are consulted first, in order.
3. **Streaming intercepts**: methods that take over the connection and are matched before routes.

Method sets here are the registration points; per-method parameters and results live in each handler. Where a handler module is named, its source file is under `crates/clawft-weave/src/`.
