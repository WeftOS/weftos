## `weaver`

```text
WeftOS operator CLI — kernel, agents, and system management

Usage: weaver [OPTIONS] <COMMAND>

Commands:
  kernel     Kernel management (boot, status, services, processes)
  project    Per-project kernel operations (migrate-kernel)
  agent      Agent lifecycle management (spawn, stop, restart, inspect)
  app        Application management (install, start, stop, list)
  workload   Governed workloads placed across the mesh (ADR-099)
  model      Adopt, verify and explain locally held model weights (ADR-101)
  cog        Project cog sources (WeftOS, Cognitum, private), licences, search, install (ADR-105)
  mesh       Machine mesh service: serve it, inspect it, administer bindings and peers (ADR-103)
  cluster    Cluster management (nodes, shards, health)
  fleet      Fleet manager: every known node with trust, last seen, cogs and location
  dashboard  Dashboard reporter: status and token rotation (locally or on a peer)
  expose     What this node exposes to the mesh: list, on, off, pause, log (ADR-120)
  cogbus     The node's cog data plane broker: list topics (ADR-122)
  route      Tailnet router: routes, reload, and the Tailscale Serve front door (ADR-116)
  chain      Chain management (status, events, checkpoints)
  custody    Custody attestation (signed proof of system state)
  resource   Resource tree management (tree, inspect, stats)
  soul       Identity-journal operator commands (promote, status)
  cron       Cron job management (add, list, remove)
  ipc        IPC management (topics, subscribe, publish)
  console    Interactive kernel console (boot + REPL, or attach to running kernel)
  ecc        ECC cognitive substrate management (status, calibrate, search)
  graphify   Knowledge graph extraction, query, and export (graphify)
  versions   Version index of first-class objects: list, tree, deps (ADR-121)
  vault      Obsidian vault cultivation (frontmatter, links, graph analysis)
  topology   Topology layout, schema validation, and geometry detection
  leaf       Leaf device control (push audio, display, effects)
  benchmark  Run standardized kernel performance benchmark
  service    Print a launchd / systemd unit for the per-user daemon
  init       Initialize development environment (install skills, verify tools)
  update     Update weft, weaver and weftos to the latest verified release
  doctor     Check install, daemon, runtime and MCP health (read-only; `--fix` for stale files)
  migrate    Migrate WeftOS state (user chain)
  version    Show version and build info

Options:
  -v, --verbose  Enable verbose (debug-level) logging
  -h, --help     Print help
  -V, --version  Print version
```

#### `weaver cog checkout`

```text
Check out a Cognitum cog through the mesh's Seed steward, approve its hashes, or list grants and approvals (ADR-106; needs the daemon)

Usage: weaver cog checkout [OPTIONS] [REFERENCE]
       weaver cog checkout <COMMAND>

Commands:
  approve      Approve the hashes of a checked-out cog version (operator, Admin)
  status       Grants and approvals this node holds
  release      End a checkout: the steward asks the Seed for a withdrawal, which is flooded (operator, Admin; run on the steward). The same Seed call also renews every other active checkout of the mesh
  renew        Renew now instead of at the next 12-hourly pass (Admin; run on the steward). The Seed renews every active checkout in one call
  list         Held grants, approvals and expiry (read-only)
  reset-floor  Forget the grant clock high-water mark (alias of `weaver workload node reset-floor`); changes nothing without `--confirm <floor>`

Arguments:
  [REFERENCE]  `<cog>@<version>` (`latest` is allowed) to check out

Options:
  -v, --verbose      Enable verbose (debug-level) logging
      --arch <ARCH>  Target arch (default: this node's)
      --json         Print raw JSON
  -h, --help         Print help
```

##### `weaver cog checkout approve`

```text
Approve the hashes of a checked-out cog version (operator, Admin)

Usage: weaver cog checkout approve [OPTIONS] --operator-key <OPERATOR_KEY> [REFERENCE]

Arguments:
  [REFERENCE]  `<cog>@<version>` (an exact version)

Options:
      --operator-key <OPERATOR_KEY>   Operator key file (hex seed), pinned on the daemon
  -v, --verbose                       Enable verbose (debug-level) logging
      --sha256 <SHA256>               Approve exactly this sha256 (repeat); default: every artifact of the held grant
      --reapprove-orphaned            Re-sign, for the current mesh id, every approval a `mesh_nonce` change orphaned
      --confirm <CONTENT_KEY|DIGEST>  Sign and send, pinned to what the dry run printed: the approval's content key, or with `--reapprove-orphaned` the batch digest. Without it the content is shown and nothing is signed; a value that no longer matches the freshly prepared content is refused
  -h, --help                          Print help
```

##### `weaver cog source add`

```text
Add a source

Usage: weaver cog source add [OPTIONS] --kind <KIND> <NAME>

Arguments:
  <NAME>
          Name, used as the `name:cog-id` namespace

Options:
      --kind <KIND>
          `weftos`, `cognitum` or `private`

          Possible values:
          - weftos:   WeftOS / WeaveLogic signed registry
          - cognitum: Cognitum app registry (licence required to install)
          - private:  The project's own signed registry

  -v, --verbose
          Enable verbose (debug-level) logging

      --url <URL>
          registry.json / app-registry.json URL, file path or repo directory (a `cognitum` source defaults to Cognitum's public registry)

      --key <KEYS>
          Ed25519 public key (64 hex) allowed to sign this source (repeat). Required for `private`

      --priority <PRIORITY>
          Higher wins when a bare id is in several sources

          [default: 0]

      --user
          Edit the user default list instead of the project

      --allow-insecure
          Development only: let a cognitum source use http:// or a local path

  -h, --help
          Print help (see a summary with '-h')
```

### `weft agent`

```text
Start an interactive agent session or send a single message

Usage: weft agent [OPTIONS]

Options:
  -m, --message <MESSAGE>
          Send a single message and exit (non-interactive mode).

          Each `-m` turn starts a fresh conversation with no prior history unless `--session` names one to continue.

  -v, --verbose
          Enable verbose (debug-level) logging

      --project <ULID>
          Use the kernel serving this project (ULID; see `weft project list`)

      --session <ID>
          Continue a named conversation with `-m` (letters, digits, `.`, `_`, `-`; up to 128 characters). Two `-m` calls with the same `--session` share history. The interactive REPL keeps its own `cli-session` conversation and does not take this flag

      --model <MODEL>
          Model to use (overrides config)

      --runtime <DIR>
          Use the kernel whose runtime directory is DIR (overrides WEFTOS_RUNTIME_DIR)

  -c, --config <CONFIG>
          Config file path (overrides auto-discovery)

      --intelligent-routing
          Enable intelligent routing (requires vector-memory feature)

      --local
          Run the agent loop inside this process when no kernel daemon is reachable. Without it, a missing daemon is an error: an in-process agent can run tools and write files the daemon never sees

      --trust-project-skills
          Trust workspace-level (project) skills.

          Without this flag, only user and built-in skills are loaded. Workspace skills in `.clawft/skills/` are skipped as a security measure (SEC-SKILL-05).

  -h, --help
          Print help (see a summary with '-h')
```
