# MCP spec 2026-07-28 audit

**Date:** 2026-10-11
**Status:** Research capture (not an ADR). Source card: watch review 2026-10, item B8.
**Primary source:** the specification changelog at `modelcontextprotocol.io/specification/2026-07-28/changelog` ("Key Changes"). The first pass (2026-10-11) used a summarising fetch; section 6 records the re-read of the raw pages on 2026-10-12.

The repo implements `2025-06-18` (`MCP_PROTOCOL_VERSION` in `crates/clawft-services/src/mcp/mod.rs`), accepting `2024-11-05`, `2025-03-26` and `2025-06-18` from peers. Nothing here implements 2025-11-25 either, so the real gap is two revisions.

## 1. What changed in 2026-07-28

### Major (wire-breaking)

1. **No protocol sessions.** `Mcp-Session-Id` is removed from Streamable HTTP; list endpoints may no longer vary per connection. Cross-call state uses server-minted handles passed as ordinary tool arguments (SEP-2567).
2. **Stateless core.** The `initialize` / `notifications/initialized` handshake is gone. Every request carries `io.modelcontextprotocol/protocolVersion` and `.../clientCapabilities` in `_meta`; clients should add `.../clientInfo`, servers should return `.../serverInfo` in result `_meta`. Version mismatch returns `UnsupportedProtocolVersionError` (SEP-2575).
3. **`server/discover`** is a new mandatory server RPC (versions, capabilities, identity). Clients may call it first, or use it as a stdio compatibility probe (SEP-2575).
4. **`subscriptions/listen`** replaces the HTTP GET endpoint and `resources/subscribe` / `unsubscribe`: one long-lived POST-response stream, opt-in per notification type (`toolsListChanged`, `promptsListChanged`, `resourcesListChanged`, `resourceSubscriptions`). Progress and log notifications stay on the originating request's stream (SEP-2575).
5. **Removed:** `ping`, `logging/setLevel`, `notifications/roots/list_changed`. Log level is per request via `io.modelcontextprotocol/logLevel`; servers must not emit `notifications/message` otherwise (SEP-2575).
6. **Tasks leave the core** and become the official extension `io.modelcontextprotocol/tasks`: polling via `tasks/get`, new `tasks/update`, `tasks/result` and `tasks/list` removed, unsolicited task handles allowed (SEP-2663).
7. **Multi Round-Trip Requests (MRTR)** replace server-initiated requests (`roots/list`, `sampling/createMessage`, `elicitation/create`): the server returns an `InputRequiredResult` and the client retries with `inputResponses` (SEP-2322).
8. **Every result carries `resultType`** (`"complete"` or `"input_required"`). Clients must treat a missing field from older servers as `"complete"` (SEP-2322).
9. **SSE resumability removed** (`Last-Event-ID`, event ids). A broken stream loses the in-flight request; the client re-issues it with a new id (SEP-2575).

### Minor, but code-visible

- New `extensions` field in client and server capabilities.
- OpenTelemetry trace context in `_meta` (`traceparent`, `tracestate`, `baggage`; SEP-414).
- `tools/list` should be deterministic in order.
- Streamable HTTP POST must carry `Mcp-Method` and `Mcp-Name` headers; `x-mcp-header` custom headers from tool params (SEP-2243).
- `ttlMs` and `cacheScope` required on `tools/list`, `prompts/list`, `resources/list`, `resources/read`, `resources/templates/list` (SEP-2549).
- Resource-not-found error code `-32002` becomes `-32602`.
- Error code policy: `-32000..-32019` implementation-defined, `-32020..-32099` reserved for MCP (`HeaderMismatch` -32020, `MissingRequiredClientCapability` -32021, `UnsupportedProtocolVersion` -32022).
- Auth: `iss` per RFC 9207 must be validated by clients (SEP-2468); `application_type` required in dynamic client registration (SEP-837); client credentials bound to the issuing authorization server (SEP-2352).
- `inputSchema` / `outputSchema` accept any JSON Schema 2020-12 keywords; `structuredContent` may be any JSON value (SEP-2106).
- `notifications/elicitation/complete` and `elicitationId` removed.

### Deprecated (twelve-month window under the new lifecycle policy, SEP-2596)

Roots, Sampling and Logging (SEP-2577); the HTTP+SSE transport; `includeContext` values `thisServer` / `allServers`; OAuth Dynamic Client Registration in favour of Client ID Metadata Documents.

## 3. Compatibility risk worth naming

- **Servers we run are stateful in one specific way.** `McpServerShell` refuses `tools/list` and `tools/call` until an `initialize` has been seen, and the HTTP listener shares a single shell across all clients. A 2026-07-28 client never sends `initialize`, so against our server today it would be rejected on a fresh process, and would work only by accident after some other client had initialised the shared shell. That mismatch is the first thing a newer host would hit, and it will appear when Claude Code, Codex or Grok move to the new revision.
- **Dual-mode is mandatory for years.** The deprecation policy gives twelve months minimum, and servers in the wild upgrade unevenly. Every change above should keep the 2025-06-18 path alive.
- **Three JSON-RPC clients and two servers** (shell, graphify stdio, plus `fleet_mcp`) exist. Each protocol change is paid for several times. Consolidating onto the shell and `McpSession` before the migration is cheaper than patching each.

## 4. Ranked action list

1. **Make `McpServerShell` stateless-capable and add `server/discover`** (item 1, M). Largest compatibility exposure, and everything else builds on it. Keep `initialize` for legacy clients, selected by the presence of the `_meta` version fields.
2. **Add `resultType`, `ttlMs` / `cacheScope`, deterministic tool order** (items 1 and 6, S). Small and mechanical once the dispatch is touched.
3. **Update `mcp-server-smoke.yml` with a stateless job** (item 9, S) so the change in step 1 is covered; do this in the same change.
4. **Make `McpSession` / `McpClient` dual-mode** (item 4, L): discover-first with an `initialize` fallback, drop `ping` keepalive, move list-changed refresh to `subscriptions/listen` where the peer supports it.
5. **Route `clawft-graphify`'s stdio MCP server through the shared shell** (item 10, S to M) instead of fixing a second copy.
6. **Bring `fleet_mcp.rs` up to the new auth rules and `_meta` fields**, and fold it onto the shared client if feasible (item 12, M).
7. **HTTP headers and subscriptions in the listeners** (items 2 and 3, M): `Mcp-Method` / `Mcp-Name`, then `subscriptions/listen` to replace `GET /mcp/sse`. Do last; the GET stream is a keepalive only, so nothing depends on it.
8. **Hold the ruflo pin and the host clients** until a 2026-07-28 build exists (item 16); recheck at each bump.
9. **Skip entirely:** Sampling, Roots, Logging, Elicitation, MRTR and Tasks-extension support. We use none of them, and the first four are deprecated. Revisit MRTR and the Tasks extension only if a tool needs long-running or interactive work over MCP.

Suggested sequencing: steps 1 to 3 as one card, step 4 as a second, steps 5 to 7 as a third. No card is filed from this document.

## 6. Verification against the primary source (2026-10-12)

Raw pages fetched with curl: the changelog, `basic/versioning`, `basic/transports/stdio`, `basic/transports/streamable-http` and `schema` (the `DiscoverResult` section). Result: every item in section 1 is confirmed. Corrections and additions:

- **The previous revision is 2025-11-25**, and the changelog diffs against it. The changes between 2025-06-18 and 2025-11-25 are not in section 1; "two revisions" of gap stands.
- **Error codes are renumbered** in this revision: `HeaderMismatch` -32001 -> **-32020**, `MissingRequiredClientCapability` -32003 -> **-32021**, `UnsupportedProtocolVersion` -32004 -> **-32022**. Section 1 already lists the final numbers; any draft-era SDK using the old ones is stale.
- **`DiscoverResult`** is `{resultType, supportedVersions[], capabilities, instructions?, ttlMs, cacheScope, _meta?}`; it is itself a cacheable result and identifies the server through `_meta["io.modelcontextprotocol/serverInfo"]`.
- **Dual-era servers are explicitly allowed.** A request with modern `_meta` is served statelessly; an `initialize` request selects legacy semantics scoped to the stdio process or HTTP session. Era is a per-message decision.
- **stdio probe:** a client sends `server/discover` first; a `DiscoverResult` or a recognised modern error (-32022) means modern, any other error or silence means legacy and the client falls back to `initialize`. A bare `server/discover` (without `_meta`) must therefore be answerable by a legacy-capable server.
- **HTTP:** every modern POST carries `MCP-Protocol-Version` (must equal the body `_meta` value), `Mcp-Method` (all requests) and `Mcp-Name` (`tools/call`, `prompts/get` -> `params.name`, `resources/read` -> `params.uri`). Missing or mismatched headers: `400` with `HeaderMismatch` (-32020). Unsupported version: `400` with `UnsupportedProtocolVersionError` whose `data` is `{supported, requested}`. Unknown method: `404` with JSON-RPC -32601. `Mcp-Name` may be base64-sentinel encoded (`=?base64?...?=`) for non-ASCII values; not yet decoded by this repo.
- `ttlMs`/`cacheScope` are required on `tools/list` results (confirmed) and on `server/discover`.

## 7. Implemented on `wt/mcp` (card 5856df13)

- `McpServerShell` serves stateless requests (version in `params._meta`) and `server/discover` with no handshake and no shell state; `initialize` still selects the 2025-06-18 path. Legacy results are unchanged (no `resultType`/cache fields) so 2025-06-18 clients see the same bytes. Modern results get `resultType: "complete"`, `_meta` serverInfo, and `ttlMs: 0` / `cacheScope: "private"` on list results (tool lists are session-scoped by token and change on hot-reload, so no positive TTL, no shared caching).
- `tools/list` is sorted by name in both eras. `ping` is rejected as an unknown method in the modern era (removed by the spec); legacy `ping` is kept.
- `weft mcp-server --listen` and the gateway `/mcp` mount validate the mirror headers for modern requests and map -32020 / -32022 to HTTP 400. Modern requests never touch the shared shell's `initialized` flag, so a legacy `initialize` from one client cannot enable or disable another client's stateless calls. Legacy requests over HTTP still share that one flag (unchanged; there is no session id to key on).
- CI: `scripts/ci/mcp_smoke_stateless.py`, run as a second step of the existing smoke job (shares its build).
- Not done: `Mcp-Name` base64 decoding, `subscriptions/listen`, `MissingRequiredClientCapability`, dropping `GET /mcp/sse` (kept for legacy peers), `clawft-graphify`'s stdio server. The graphify server was left alone on purpose: it avoids a `clawft-services` dependency by design (its own header says so), so folding it onto the shell means adding that dependency plus a `ToolProvider` adapter over its tool table, which is more than a small change. Until then it is legacy-only.
